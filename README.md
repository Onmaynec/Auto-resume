# ✨ Auto Resume v2.2

> Устанавливаемое веб-приложение, которое превращает GitHub-профиль в адаптированное под вакансию резюме и сохраняет рабочие черновики локально.

## 🆕 Что нового в v2.2

- 📲 **Progressive Web App**: Auto Resume можно установить на компьютер или телефон.
- 🌐 **Offline app shell**: после первого посещения интерфейс открывается без сети.
- 💾 **Локальные черновики**: создавайте несколько именованных версий резюме под разные вакансии.
- ✍️ **Автосохранение**: изменения активного черновика сохраняются после редактирования текста и смены шаблона.
- 📦 **JSON backup**: экспортируйте черновики, тему и недавние профили, затем импортируйте их в другом браузере.
- 🧹 **Управление кэшем**: очищайте только GitHub API-кэш, не затрагивая черновики и настройки.
- 📡 **Статус сети и свежесть данных**: интерфейс показывает online/offline режим и время получения профиля.

## 🚀 Возможности

- анализ публичного GitHub-профиля и до 100 репозиториев;
- языки, topics, звёзды, форки и годовая активность;
- сравнение двух GitHub-профилей;
- анализ требований вакансии без внешнего AI API;
- выбор и сортировка проектов;
- редактируемые Visual и ATS-шаблоны;
- Visual PDF, ATS PDF, TXT и публичная ссылка;
- светлая, тёмная и системная темы;
- недавние профили;
- PWA, offline shell и локальное рабочее пространство.

## 📲 Установка PWA

Откройте production-версию по HTTPS. Когда браузер подтвердит installability, в верхней панели появится кнопка **«Установить»**. Также приложение можно установить через меню браузера.

Service Worker кэширует только оболочку приложения и статические модули. Запросы к `/api/github` всегда идут в сеть и не сохраняются Service Worker-ом.

## 💾 Черновики

После генерации резюме автоматически создаётся локальный черновик. Для него доступны:

- сохранение под собственным названием;
- автоматическое обновление после редактирования;
- повторное открытие без загрузки GitHub-профиля;
- переименование;
- удаление;
- отдельный Visual или ATS шаблон.

Черновики хранятся в `localStorage` под ключом `auto-resume:workspace:v1` и не отправляются на сервер.

## 📦 Резервные копии

Кнопка **«Экспорт JSON»** сохраняет:

- все черновики;
- выбранную тему;
- список недавних профилей;
- версию формата и дату экспорта.

При импорте приложение проверяет тип, версию и структуру файла. Резервная копия не содержит серверный GitHub token.

## 🧩 Архитектура

```text
Браузер
  ├─ Service Worker → offline app shell
  ├─ /api/github?username=octocat → GitHub GraphQL API
  ├─ localStorage
  │    ├─ workspace: черновики
  │    ├─ preferences: тема и история
  │    └─ API cache с TTL
  ├─ локальный анализ вакансии и сравнение профилей
  └─ #resume=<base64url-json> → публичное резюме
```

## ☁️ Развёртывание на Vercel

1. Импортируйте репозиторий в Vercel.
2. Добавьте переменную окружения:

```text
GITHUB_TOKEN=ваш_токен
```

3. Выполните deployment.

`vercel.json` задаёт корректные заголовки для Service Worker и Web App Manifest.

## ▶️ Локальный запуск

```bash
git clone https://github.com/Onmaynec/Auto-resume.git
cd Auto-resume
python -m http.server 8080
```

Service Worker разрешён на `localhost`. Полный serverless-режим:

```bash
npm install -g vercel
printf "GITHUB_TOKEN=your_token_here\n" > .env.local
vercel dev
```

## ✅ Проверка

```bash
npm run verify
```

Команда выполняет:

- `node --check` для клиентских модулей, Service Worker и API;
- unit-тесты черновиков, backup/import и очистки кэша;
- smoke-тесты PWA manifest, Service Worker и обязательных контролов;
- существующие тесты сравнения, вакансий, экспортов и GraphQL;
- `git diff --check`.

Те же проверки запускаются GitHub Actions CI для pull request и `main`.

## 🔐 Приватность

- анализируются только публичные GitHub-данные;
- `GITHUB_TOKEN` остаётся в serverless environment variable;
- вакансии, черновики, история и тема обрабатываются локально;
- Service Worker не кэширует `/api/github`;
- JSON backup создаётся только по действию пользователя;
- PDF, TXT и публичные ссылки формируются в браузере.
