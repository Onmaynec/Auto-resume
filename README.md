# ✨ Auto Resume v2.0

> GitHub-профиль превращается в адаптированное под вакансию, редактируемое и публичное резюме разработчика.

## 🆕 Что нового в v2.0

- 🎯 **Анализ вакансии**: приложение извлекает технологии из описания, сравнивает их с языками, topics и проектами GitHub-профиля.
- 📊 **Оценка соответствия**: показывает совпавшие и отсутствующие навыки, а также процент соответствия требованиям.
- 🏆 **Релевантные проекты**: автоматически поднимает проекты, которые лучше подтверждают требования вакансии.
- 📈 **История языков по месяцам**: реальные commit contributions группируются по primary language репозитория за каждый из последних 12 месяцев.
- 🔗 **Публичные ссылки**: готовое резюме кодируется в URL-фрагмент и может быть открыто без базы данных и регистрации.
- 🔒 **Privacy by design**: данные публичного резюме не отправляются серверу — URL-фрагменты не входят в HTTP-запрос.
- ✍️ Сохранены редактирование текста, выбор и сортировка проектов, Visual/ATS-шаблоны, TXT и PDF-экспорт из v1.1.

## 🚀 Возможности

- профиль: имя, аватар, био, локация, подписчики и количество репозиториев;
- репозитории: описание, topics, языки, звёзды, форки и ссылка;
- годовой contribution heatmap;
- график «Динамика активности» по месяцам;
- stacked-график истории языков;
- детерминированный локальный анализ вакансии без отправки её текста стороннему ИИ;
- выбор до пяти проектов и сортировка drag-and-drop или стрелками;
- редактирование резюме прямо в макете;
- Visual PDF через `html2canvas` + `jsPDF`;
- ATS-friendly PDF через печать браузера с настоящим текстовым слоем;
- UTF-8 TXT-экспорт;
- публичная ссылка на готовое резюме.

## 🧩 Архитектура

```text
Браузер
  ├─ /api/github?username=octocat
  │    └─ GitHub GraphQL API
  ├─ локальный анализ вакансии
  └─ #resume=<base64url-json> — публичное резюме без серверного хранения
```

Serverless endpoint одним GraphQL-запросом получает:

- публичный профиль;
- до 100 оригинальных репозиториев;
- языки и topics;
- contribution calendar за год;
- commit contributions по репозиториям отдельно для каждого месяца.

История языков — это не оценка байтов кода. Она показывает **реальные commit contributions пользователя**, сгруппированные по основному языку репозитория в соответствующем месяце.

## 🎯 Как работает анализ вакансии

1. Из текста выделяются распространённые технологии и практики: TypeScript, React, Python, Docker, SQL, AWS, CI/CD и другие.
2. Требования сравниваются с языками, topics, названиями и описаниями репозиториев.
3. Приложение вычисляет процент совпадения.
4. Проекты получают relevance score и автоматически сортируются для резюме.
5. Заголовок и секция «О себе» дополняются подтверждёнными навыками.

Анализ выполняется в браузере и не отправляет текст вакансии во внешние AI API.

## 🔗 Публичные ссылки

Кнопка **«Скопировать публичную ссылку»** формирует URL вида:

```text
https://example.vercel.app/#resume=<encoded-data>
```

URL-фрагмент после `#` не отправляется веб-серверу. В нём находятся только данные готового резюме: имя, заголовок, контакты, описание, выбранные проекты и навыки. Не добавляйте в резюме сведения, которые не должны быть публичными.

## ☁️ Развёртывание на Vercel

1. Импортируйте репозиторий в Vercel.
2. Откройте **Project Settings → Environment Variables**.
3. Добавьте:

```text
GITHUB_TOKEN=ваш_токен
```

4. Выполните новый deployment.

Токен используется только `api/github.js` и никогда не отправляется в браузер.

## ▶️ Локальный запуск

Экономный REST fallback:

```bash
git clone https://github.com/Onmaynec/Auto-resume.git
cd Auto-resume
python -m http.server 8080
```

Полный режим:

```bash
npm install -g vercel
printf "GITHUB_TOKEN=your_token_here\n" > .env.local
vercel dev
```

## ✅ Проверка

```bash
npm run verify
```

Команда выполняет:

- синтаксическую проверку всех JavaScript-модулей;
- unit-тесты выбора проектов;
- тесты анализа вакансии;
- round-trip тест публичной ссылки с Unicode;
- тесты ATS TXT-экспорта;
- тесты построения 12-месячного GraphQL-запроса;
- smoke-тест обязательной HTML/CSS-разметки;
- `git diff --check`.

## 🔐 Приватность

- анализируются только публичные данные GitHub;
- GitHub token хранится в serverless environment variable;
- текст вакансии анализируется локально;
- профили не сохраняются в базе данных;
- serverless и браузерный кэш автоматически устаревают;
- публичное резюме хранится в URL пользователя, а не на сервере;
- PDF и TXT создаются непосредственно в браузере.
